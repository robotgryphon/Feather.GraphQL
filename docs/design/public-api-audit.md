# Public API audit

A survey of every type the four shipping assemblies export, what each is for, and whether it
needs to be public. Generated by reflecting over the built assemblies, then tracing each type's
references back through the source — so "unused" below means *no reference anywhere in `src`,
`tests` or `examples`*, not merely "looks unused".

**27 public types**, down from 36.

| Assembly | Was | Now |
| --- | ---: | ---: |
| `Feather.GraphQL.Abstractions` | 7 | **4** |
| `Feather.GraphQL.Http` | 7 | **3** |
| `Feather.GraphQL.Linq` | 19 | **17** |
| `Feather.GraphQL.Linq.Providers.HttpClient` | 3 | 3 |

Applied: `StringUtils` deleted; `ErrorPathConverter` internal; `GraphQLQueryPlan` internal, taking
`QueryResultOperator` with it; the response-wrapper hierarchy replaced by "return the data, or
throw", removing five interfaces; and `HttpClientExtensions` merged into `HttpExtensions` with its
request-building helpers made private. Outstanding: `GraphQLHttpConstants` (internal),
`IConfigurableExtensions` (delete), the `Metadata` trio, and `HttpGraphQLQueryExecutor`.

---

## Feather.GraphQL.Abstractions

What a failed query looks like, whatever carried it. Its two response interfaces were removed
outright (below), leaving types that describe what a server reports rather than how it was
reached.

| File | Type | What it is for | Verdict |
| --- | --- | --- | --- |
| `GraphQLException.cs` | `GraphQLException` | **Abstract.** A failed query and the errors the server gave. A transport derives from it to add what only it can supply, so code that cares only that the query failed catches this and never names a transport. | **Keep** |
| `Primitives/GraphQLError.cs` | `GraphQLError` | One entry of the `errors` array: message, locations, path, extensions. | **Keep** |
| `Primitives/GraphQLLocation.cs` | `GraphQLLocation` | Line and column of an error in the query document. | **Keep** |
| `Primitives/ErrorPath.cs` | `ErrorPath` | An error's `path` — field names and list indices. | **Keep** |
| `Converters/ErrorPathConverter.cs` | — | Internal. Reachable only through `[JsonConverter]` on `ErrorPath`. | Internal |

**Why it is a package rather than part of Http.** It briefly was not: with only three types and
one consumer, folding it into `Feather.GraphQL.Http` looked like the same win that removed
`Linq.Abstractions`. That reasoning counted today's consumers, not tomorrow's. A websocket or
gRPC transport reports the same errors, and making it depend on `HttpClient` to name a
`GraphQLError` would be exactly the coupling the rest of this layout avoids. The package stays,
and it stays small on purpose.

**The exception is split for the same reason, and it is the one place the surface grew.**
`GraphQLException` was HTTP's, carrying an `HttpResponseMessage` — which meant a second transport
would define its own and a caller handling both would need two `catch` blocks. It is now abstract
here, holding only `Errors`, and `GraphQLHttpException` derives from it in `Http`. One type more
than before, in exchange for a failure contract that outlives the transport that raised it.

The move out cost one project file and no code, because the types kept the
`Feather.GraphQL.Primitives` namespace throughout — worth remembering the next time a
consolidation looks free.

## Feather.GraphQL.Http

One extension class for the whole transport — sending a precompiled query string and reading the
reply — plus the HTTP form of a failure. The error model and the base exception live in
`Abstractions`.

### The shape that replaced the wrappers

A reply used to come back as `IGraphQLHttpDataResponse<T>` — data, errors, extensions, headers
and status — which every caller had to unpack and then check for errors the status code had not
reported. Now the success path returns the data and the failure path throws:

```csharp
PersonResponse data = await response.ReadGraphQLAsync<PersonResponse>(ct);
// or GraphQLException { Errors, Response }
```

That removed **five** public types at once: `IGraphQLResponse`, `IGraphQLDataResponse<T>`,
`IGraphQLHttpResponse`, `IGraphQLHttpDataResponse<T>` and `GraphQLHttpResponseExtensions`, plus
the internal `GraphQLHttpResponse`. Two extensions collapsed into one: `AsDataResponse<T>` and
`ReadAsGraphQLAsync<T>` did nearly the same thing on different receivers, and the exception needs
the `HttpResponseMessage` anyway, so only the one on the response survives.

| File | Type | What it is for | Verdict |
| --- | --- | --- | --- |
| `HttpExtensions.cs` | `HttpExtensions` | The whole transport: `SendGraphQLQueryAsync` and `ReadGraphQLAsync<T>` public, the request-building helpers **private**. | **Keep** |
| `GraphQLHttpException.cs` | `GraphQLHttpException` | A failed query over HTTP: the base's `Errors`, plus the live `Response`. Catch the base to ignore the transport; catch this to read status, headers or body. | **Keep** |
| `GraphQLHttpConstants.cs` | `GraphQLHttpConstants` | `RESPONSE_CONTENT_TYPES`, the `Accept` values. Read only by `AddGraphQLRequestHeaders`, which is now private — so nothing reachable uses it. | **Internal** |
| `IConfigurableExtensions.cs` | — | Internal already. `New<TOptions>` and `AndReturn<TOptions>`, **referenced nowhere but each other.** | **Delete** |

### What the merge did

`HttpClientExtensions` folded into `HttpExtensions`, and the change went further than the audit
asked. `AsHttpPost`, `AsHttpMessageContent` and `AddGraphQLRequestHeaders` did not become
internal — they became **private**, which closes the arbitrary-object-to-wire hatch outright
rather than merely hiding it from other packages. `SendMutationAsync` went too: it was
byte-identical to `SendGraphQLQueryAsync`, because a mutation is a document like any other.

Two things worth noticing in passing:

- The serializer options are now a `static readonly` field rather than a fresh instance per
  call. That is a real fix, not tidying: `System.Text.Json` caches type metadata **per options
  instance**, so a new one per request defeated the cache on every send.
- Reads and writes now use different options objects — `SERIALIZER_OPTS` for the request,
  `JsonSerializerOptions.Web` for the reply. They agree today (both camelCase and
  case-insensitive), so nothing is broken; but it is two sources of truth for one wire format,
  and the read path could take `SERIALIZER_OPTS` instead.

### Two things the new shape forced

**The response is not disposed when the read throws.** A failure is exactly when the raw body
matters — a 502 HTML error page explains more than any status code — so `GraphQLHttpException`
holds a live `HttpResponseMessage` and disposal passes to the handler. `HttpGraphQLQueryExecutor`
therefore disposes explicitly on the success path rather than with `using`.

**"No data" needed an exact answer.** Deserializing `data` straight into `TData` leaves a value
type at its default, and `default(JsonElement)` is indistinguishable from a legitimately empty
one — a `{}` reply slipped through as success and failed later in the materializer. `data` is now
read as a `JsonElement` first, so the check is on `ValueKind`, and the caller's type is
deserialized from it afterwards.

### The source generator's contract

`TypeMetadataGenerator` now emits field tables and calls `Register` from a module initializer in
the **consumer's** assembly — so these three are load-bearing public API, not speculative. They
were flagged *Internal* while nothing generated; that is no longer true.

| File | Type | What it is for | Verdict |
| --- | --- | --- | --- |
| `Metadata/IGraphQLTypeMetadata.cs` | `IGraphQLTypeMetadata` | A type's CLR-member → GraphQL-field table. Implemented by generated code. | **Keep** |
| `Metadata/GraphQLFieldMetadata.cs` | `GraphQLFieldMetadata` | One member of that table. Constructed by generated code. | **Keep** |
| `Metadata/GraphQLTypeMetadataRegistry.cs` | `GraphQLTypeMetadataRegistry` | Where generated metadata registers itself at assembly load. Called from generated code in the consumer's assembly. | **Keep** |

That bet is settled: the generator landed, so all three stay public. Reflection survives only as
the fallback for element types the generator cannot see.

The only assembly referencing both `Linq` and `Http`.

| File | Type | What it is for | Verdict |
| --- | --- | --- | --- |
| `HttpClientGraphQLQueryableExtensions.cs` | `HttpClientGraphQLQueryableExtensions` | `CreateQueryable<T>(rootField, …)` — the whole public surface of the transport. | **Keep** |

the only way to reach HTTP. Niche, but real.

## Member-level trims

Cuts that shrink the surface without removing a type.

- **`HotChocolateFilterProvider`** exposes 23 members because it implements the interface. Only
  `Instance` is used from outside; the operator properties are visible as a consequence.
- **`ErrorPath`** derives from `List<object>`, so its public surface is all of `List<object>`.
  A read-only wrapper would be narrower, at the cost of a breaking change for anyone indexing it.

## Known sharp edge

`GraphQLWhereExtensions.Where<TFilter>(Expression<Func<TFilter, bool>>)` collides with LINQ's own
`Where` whenever a **prebuilt** `Expression<Func<T, bool>>` is passed and
`Feather.GraphQL.Linq.Filtering` is imported. Inline lambdas and the two-argument
`Where(argumentName, predicate)` form are unaffected. Giving the single-argument filter-shape
overload its own name would remove the collision and cost one rename.
